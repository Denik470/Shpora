Экзамен: что делать и чем проверить

Краткая памятка по учебному стенду. Работает без интернета, внешних библиотек и шрифтов.

Перед началом. На экзамене используй памятку только в разрешённом формате. Адреса ниже — из учебного сайта; экзаменационный лист имеет приоритет. Это маршрут и команды проверки, а не готовый установочный скрипт. Всё в <угловых скобках> замени своим значением без скобок. etcnet: где менять настройки

Только если интерфейс действительно управляется etcnet. Перед изменениями сохрани копии существующих файлов. В примере IFACE — условное имя каталога: замени его своим интерфейсом.

Файл /etc/net/ifaces/IFACE/options · обычный Ethernet, статический адрес
TYPE=eth
BOOTPROTO=static
ONBOOT=yes
CONFIG_IPV4=yes
DISABLED=no
NM_CONTROLLED=no
SYSTEMD_CONTROLLED=no

ipv4address в том же каталоге: одна строка вида 192.168.100.2/27. ipv4route: default via 192.168.100.1 — только если это нужный шлюз этой машины. Эти строки записываются в файлы, а не вводятся как команды.

Для VLAN нужны отдельные параметры типа, родительского порта и VLAN ID: этот Ethernet-шаблон их не заменяет. Внешний интерфейс ISP получает DHCP согласно варианту.

После сохранения · из консоли VirtualBox
systemctl restart network
ip -br addr
ip route

Перезапуск сети может оборвать SSH. В nano: Ctrl+O → Enter — сохранить; Ctrl+X — выйти. Ctrl+C — остановить команду.

01. Старт: машина, права, интерфейсы

Перед любым изменением проверь, на какой машине работаешь. Имена интерфейсов из примеров заменяй своими.

Проверки · значения в скобках заменить
hostname
id
cat /etc/os-release
ip -br link
ip -br addr
ip route

uid=0 — права root. Если их нет, используй выданный способ входа администратора. MAC-адрес из VirtualBox помогает сопоставить адаптер и интерфейс Linux.

02. IP, шлюз и etcnet

Сначала настрой физические подключения и адреса. На обычном сервере нужен default route к своему маршрутизатору; на внутренних портах маршрутизатора отдельный default не нужен.

Проверки · значения в скобках заменить
ip -br addr
ip route
ping -c 3 <IP_СВОЕГО_ШЛЮЗА>
systemctl is-active network
systemctl is-active NetworkManager

Нет адреса → проверь интерфейс и его конфигурацию. Нет связи со шлюзом → маска, сегмент VirtualBox, VLAN, состояние порта. Не управляй одним интерфейсом одновременно через etcnet и NetworkManager.

03. VLAN

Сначала проверь способ передачи VLAN на экзаменационном стенде. В учебной схеме VirtualBox метки создаются внутри Linux; готовый стенд может быть устроен иначе.

Проверки · значения в скобках заменить
ip -d link show
ip -br addr
ping -c 3 <ШЛЮЗ_ЭТОГО_VLAN>

Проверь номер VLAN, родительский интерфейс, адрес на VLAN-интерфейсе. Не назначай один и тот же IP одновременно физическому интерфейсу и VLAN.

04. Маршрутизация, GRE, OSPF

Добейся связи между внешними адресами маршрутизаторов, затем между адресами GRE, затем между удалёнными подсетями.

Проверки · значения в скобках заменить
ip route
ip route get <УДАЛЁННЫЙ_IP>
ip tunnel show
sysctl net.ipv4.ip_forward
vtysh -c "show ip ospf neighbor"
vtysh -c "show ip route"

Команды vtysh — если используется FRR. Нет соседей OSPF → проверь GRE, адреса, area, passive-interface и фильтрацию. Есть маршрут туда, но нет ответа → проверь обратный маршрут и firewall.

05. Интернет и NAT

Проверяй последовательно: шлюз → внешний IP → имя сайта. NAT настраивай на предусмотренных заданием узлах.

Проверки · значения в скобках заменить
ping -c 3 <СВОЙ_ШЛЮЗ>
ping -c 3 1.1.1.1
getent hosts example.com
sysctl net.ipv4.ip_forward
nft list ruleset

Ping может блокироваться: отсутствие ответа не доказывает обрыв. Если внешний IP доступен, а имена не разрешаются — сначала DNS. Для iptables используй iptables -t nat -S и iptables -S; не очищай правила вслепую.

06. Пользователи, sudo и SSH

Создай нужные учётные записи и права по заданию. Проверяй новый SSH-вход до закрытия действующего сеанса.

Проверки · значения в скобках заменить
id <ПОЛЬЗОВАТЕЛЬ>
visudo -c
sshd -t
ss -lntp
ssh -p <ПОРТ> <ПОЛЬЗОВАТЕЛЬ>@<IP>

Connection refused → служба или порт. Timeout → маршрут/фильтрация. Permission denied → пользователь, пароль, ключ и политика SSH. Порт 2027 используй только если он указан в твоём варианте.

07. DHCP

Сначала работоспособный VLAN клиента и адрес шлюза, затем DHCP. Клиент должен получить адрес, маску, шлюз и DNS из задания.

Проверки · значения в скобках заменить
ip -br addr
ip route
cat /etc/resolv.conf
journalctl -u <СЛУЖБА_DHCP> -n 40 --no-pager

Нет аренды → интерфейс прослушивания, подсеть, диапазон, сегмент и firewall. Не выдавай адрес сервера или шлюза клиенту. Имя службы зависит от установленного пакета.

08. DNS

Проверь службу сначала на самом DNS-сервере, затем с клиента. Проверяй прямую и обратную запись, если требуется.

Проверки · значения в скобках заменить
getent hosts hq-srv.au-team.irpo
dig @<IP_DNS> hq-srv.au-team.irpo
dig @<IP_DNS> -x <IP_СЕРВЕРА>
ss -lntup

dig требует установленной утилиты. Если dig к нужному серверу работает, а getent нет — проверь DNS клиента и порядок разрешения имён. Для BIND доступны named-checkconf и named-checkzone; применяй их только при использовании BIND.

09. Время, Chrony и домен

Перед вводом клиента в домен настрой DNS домена и синхронизацию времени. Команды управления доменом выбирай под фактическую службу: Samba AD и FreeIPA различаются.

Проверки · значения в скобках заменить
timedatectl
chronyc tracking
chronyc sources -v
getent passwd <ДОМЕННЫЙ_ПОЛЬЗОВАТЕЛЬ>
id <ДОМЕННЫЙ_ПОЛЬЗОВАТЕЛЬ>

Ошибка доменного входа → сначала DNS, время, доступность контроллера и формат логина. Для CSV проверь разделитель, кодировку и соответствие полей. Не запускай повторный импорт без проверки уже созданных пользователей.

10. RAID0 и NFS

Перед RAID сверь диски по размеру и назначению. RAID0 не защищает от потери диска. Создание массива и файловой системы может уничтожить данные.

Проверки · значения в скобках заменить
lsblk -f
cat /proc/mdstat
findmnt
exportfs -v
findmnt -t nfs,nfs4
df -h

Не копируй имена дисков из примера. Для NFS проверь экспорт на сервере, путь, разрешённую подсеть и права на каталог. Монтирование должно переживать перезагрузку, если этого требует задание.

11. Ansible и инвентаризация

Сначала обычный SSH, затем inventory и Ansible. Выполняй команды из каталога нужного проекта либо указывай полный путь.

Проверки · значения в скобках заменить
ansible-inventory -i <INVENTORY> --list
ansible all -i <INVENTORY> -m ping
ansible-playbook -i <INVENTORY> <PLAYBOOK> --syntax-check

Ansible ping проверяет SSH и возможность запустить модуль, это не ICMP. UNREACHABLE → адрес, порт, ключи, пользователь. FAILED → читай причину конкретной задачи. Проверь реальные файлы отчёта об инвентаризации.

12. Docker, Apache и MariaDB

Сначала сервис на самом сервере, затем доступ клиента. Для приложения проверь контейнеры, порты и соединение с базой.

Проверки · значения в скобках заменить
docker ps -a
docker logs --tail 40 <КОНТЕЙНЕР>
ss -lntp
curl -I http://<IP>:<ПОРТ>
mariadb -u <ПОЛЬЗОВАТЕЛЬ> -p

Docker: порт контейнера и опубликованный порт хоста могут отличаться. Apache в ALT может использовать httpd2; имя службы и конфигурацию уточняй по установленному пакету. Не вставляй пароль базы прямо в командную строку.

13. Проброс, обратный прокси и HTTPS

Сначала проверь прямой доступ к приложению. Затем проброс/прокси, имя сайта, аутентификацию и сертификат. Проверяй с той стороны сети, откуда доступ требуется по заданию.

Проверки · значения в скобках заменить
nginx -t
curl -I http://<ВНУТРЕННИЙ_IP>:<ПОРТ>
curl -I https://web.au-team.irpo
openssl x509 -in <СЕРТИФИКАТ.crt> -noout -subject -issuer -dates -ext subjectAltName

502 → прокси не получает корректный ответ приложения. 401 → требуется вход. Ошибка TLS → DNS-имя, SAN, срок, время и доверенный CA. Не используй curl -k как доказательство исправного HTTPS.

14. atop, CUPS, fail2ban и резервная копия

Заверши проверкой результата каждой службы, а не только её статуса. Числа ниже сверяй с экзаменационным вариантом.

Проверки · значения в скобках заменить
systemctl status atop --no-pager
ls -lh /var/log/atop/
lpstat -v
lpstat -d
fail2ban-client status sshd
fail2ban-client get sshd maxretry
fail2ban-client get sshd bantime

В исходном учебном варианте: atop 420 секунд; fail2ban 3 ошибки, бан 60 секунд, SSH 2027. Для CUPS отправь пробную печать и найди результат. Для резервирования проверь завершение задания и восстанови тестовый файл; наличие каталога /backup не доказывает успешную копию.

15. Универсальная диагностика

Проверяй снизу вверх: интерфейс → IP → шлюз → маршрут → DNS и время → порт → служба → приложение. Меняй одну вещь за раз.

Проверки · значения в скобках заменить
systemctl status <СЛУЖБА> --no-pager
journalctl -u <СЛУЖБА> -n 50 --no-pager
ss -lntup
ip route get <IP_НАЗНАЧЕНИЯ>

Служба active ещё не означает, что клиент получает нужный результат. Перед перезапуском проверяй синтаксис поддерживаемой командой. После изменений повторяй клиентскую проверку.

Последние проверки перед сдачей

Отмечай только то, что действительно проверил на своём стенде.

Если застрял: запиши ошибку, выдели ограниченное время на диагностику, затем переходи к независимому заданию. Порядок по баллам выбирай по оценочному листу: эта памятка не устанавливает проходной балл.
